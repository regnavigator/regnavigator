# 00 · PRINCIPLES — 프론트엔드의 정체성과 책임 경계

본 문서는 medi 프론트엔드의 **무엇/왜**를 박는다.
이후 모든 spec(`01_COLOR`, `02_LAYOUT`, `03_COMPONENTS`, `04_ELEMENTS`)은 본 문서를 전제로 작성된다.

---

## 1. 정체성

> 프론트는 **에이전트의 얼굴**이다.
> 백엔드가 흘려보낸 **결과 페이로드를 일관된 시각 언어로 렌더**하고, 사용자의 입력·인터럽트 응답을 정해진 형태로 다시 백엔드에 보낸다.

프론트는 검색하지 않는다. 정리하지 않는다. 인용을 만들어내지 않는다.
프론트는 **아름답고 일관되게 보여주고, 끊김 없이 입력을 받는다**.

### 1.1 사용자

| 속성 | 값 |
|---|---|
| 주 사용자 | 의사, 의료기기 회사의 RA/QA/인허가 담당, 병원 의공학팀, 의약 법무·규제 컨설턴트 — *임상·규제 양쪽을 모두 만지는 전문가* |
| 도메인 친숙도 | 한국 법령 용어 친숙. 영어 약어(GMP·PMS·MDR·IVD 등) 친숙 |
| AI 챗봇 경험 | 있음 (ChatGPT / Claude.ai 수준 멘탈 모델 보유) |
| 가장 싫어하는 것 | **근거 없이 자신감 있는 답변** — 인용·출처가 없으면 즉시 신뢰를 잃는다 |
| 핵심 동기 | "이 문제의 *공식 근거가 무엇인지* 빨리 확인하고, 사내·고객 응대에 그대로 옮겨 쓸 수 있는가" |
| 사용 환경 | 데스크톱 1280px↑ (사무실·진료실 PC). 모바일은 부수적 |

이 프로필이 후속 spec의 우선순위를 결정한다 — `01_COLOR`(상태 색의 의미: 폐지/상충 근거 = error red), `02_LAYOUT`(라인 길이·밀도), `03_COMPONENTS`(인용 칩 1급 시민).

## 2. 멘탈 모델

`../medi-back/00_PRINCIPLES.md`와 동일한 전제:

> 사용자는 **하나의 에이전트**와 대화한다.

따라서 프론트 화면은:
- 내부 구조(supervisor / sub-agent / tool / 노드 이름)를 **노출하지 않는다**. *단계*는 백엔드가 사람의 언어로 가공한 라벨로만 보인다.
- 한 턴(turn)을 **사용자 메시지 + 단계 카드들 + 답변(+산출물)** 의 단일 단위로 표현한다.
- **단계 = 채팅 본문 안에 인라인으로**. 단계 카드는 접힌 상태가 기본이고, 클릭하면 *그 자리에서* 펼쳐져 라벨·소요 시간·도구 이름·검색 쿼리·찾은 출처 미리보기를 보여준다. 진행 중 단계는 자동 펼침, 완료 시 자동 접힘. (Claude.ai 식 tool-call 확장과 동일한 멘탈 모델.)
- **우측 패널은 두 모드만**: (a) 인용 인스펙터 — 인용 칩을 클릭했을 때 출처 본문 스니펫을, (b) 산출물 뷰어 — 보고서·문서 풀뷰. 같은 슬롯을 두 모드가 공유한다. *진행 timeline은 채팅 안에서 누적되며 우측 패널에는 두지 않는다.*

## 3. 책임 경계

### 3.1 프론트가 하는 것 (소유)

| # | 책임 |
|---|---|
| F1 | 채팅 메시지 렌더 (markdown, 스트리밍 partial) |
| F2 | 표·체크리스트·코드·인용 등 **백엔드가 보낸 구조적 페이로드** 렌더 |
| F3 | **단계 카드(Step card)** — 채팅 안 인라인 접힘/펼침, 라이브 진행 라벨, 진행/완료/오류 상태 시각 구분, 완료 시 자동 접힘 |
| F4 | 산출물 카드 + 우측 패널 산출물 뷰어 (인용 인스펙터와 슬롯 공유) |
| F5 | 사용자 입력(텍스트·파일 첨부)·인터럽트 응답·명확화 답변 |
| F6 | thread 목록·전환·새 thread |
| F7 | URL 상태 동기화 (threadId, docPath, sidebar 등) |
| F8 | 백엔드 연결 설정(배포 URL / API key) |
| F9 | 키보드 단축키·접근성·reduced-motion |
| F10 | 에러 / 재연결 표시(토스트·인라인 배너) |

### 3.2 프론트가 하지 않는 것 (백엔드 소유)

| 항목 | 누가 |
|---|---|
| 검색·검색 결과 정리 | 백엔드 |
| RAG / 출처 매칭 | 백엔드 |
| 보고서·체크리스트·비교표 **콘텐츠** 생성 | 백엔드 |
| 인용 텍스트·URL 결정 | 백엔드 |
| 진행 narration **문구** 생성 | 백엔드 (프론트는 받은 라벨 그대로 표시) |
| 다국어 응답 톤 | 백엔드 |
| PDF/DOCX 변환 | 백엔드 (프론트는 다운로드 URL만 받음) |

### 3.3 공동 책임

| 항목 | 분담 |
|---|---|
| 인터페이스 형태 | `../medi-back/02_INTERFACE.md` 양측 합의 |
| 에러 메시지 콘텐츠 | 백엔드가 사용자 향 텍스트 생성, 프론트는 시각 톤 결정 |
| 키보드 단축키 의미 | 백엔드 비관여 (프론트 고유) — 단 인터럽트 단축키는 인터페이스 영향 |

## 4. 비목표 (1차 범위 밖)

- **다크 모드 정밀 조정** — 1차는 라이트 + 시스템 prefers-color-scheme 기본만.
- **모바일 / 태블릿 반응형** — 데스크톱(>=1280px) 우선. 작은 화면은 드로워 fallback만.
- **다국어 i18n** — UI 문구 한국어 고정. 입력은 한/영 혼용 허용.
- **프린트 / PDF 직접 export** — 백엔드가 export URL을 주면 다운로드만.
- **사용자 임의 코드 실행 / 셸 콘솔** — 1차 범위 밖.
- **실시간 협업·공유 thread** — v2.
- **백엔드 응답 콘텐츠 수정/편집** — 사용자가 답변 텍스트를 직접 고치지 않는다 (재질문으로 갱신).
- **자체 검색 / 자체 RAG / 자체 추론** — 백엔드 책임. 프론트는 ***production*용 mock 모드를 만들지 않는다** — 백엔드 미배포 상태에서 프로덕션 fallback 금지. 단 ***dev/QA 전용 dummy 모드*** 는 허용 — 환경변수(`NEXT_PUBLIC_DUMMY_MODE=true`)로만 켜며, 사용자 흐름 검증용. dummy는 검색·RAG·추론을 수행하는 *척*만 한다(스크립트 stream).

## 6. 성공 기준

프론트 단독 검증 가능:

| # | 기준 |
|---|---|
| F-S1 | mock 페이로드(`../medi-back/02_INTERFACE.md` 예시)만으로 채팅·진행·답변·문서 뷰가 모두 구동된다. |
| F-S2 | 한 턴 = (사용자 + 상태 + 답변) 단일 단위로 깔끔하게 분리된다. 내부 노드 이름이 노출되지 않는다. |
| F-S3 | 스트리밍 토큰이 100ms 이내 첫 글자를 그린다(체감 즉시성). |
| F-S4 | 진행 단계가 채팅 안에서 시간순으로 누적되며, 각 카드는 접힘/펼침이 가능하다. 진행/완료/오류 상태가 시각적으로 구분된다. |
| F-S5 | `../deep-agents-ui-custom/design/screen.png`과 옆에 두고 비교했을 때 **시각 정체성이 같다**는 디자인 리뷰 합의를 받는다. |
| F-S6 | 키보드만으로 메시지 작성·전송·thread 전환·문서 닫기가 모두 가능하다. |

# 슬롯 → DRB 서식 항목 매핑

`drb-triage`가 만든 `used_slots`와 `trace`를 서식 항목에 그대로 옮긴다. **다시 판단하지 않는다.**

---

## 별지서식 10 — 데이터 활용 신청서

이 서식은 체크박스가 적고 **서술란이 많다.** 슬롯을 서술 내용에 녹여 쓴다.

| 서식 항목 | 슬롯 | 변환 |
|---|---|---|
| **IRB승인번호** | `irb_approval_status`, `irb_approval_no` | `approved` → 승인번호 기재 / `submitted` → "IRB 심의 접수 증명서 첨부(동시심의)" / `not_required` → "IRB 심의대상 아님" + 근거 |
| **처리 목적** | `data_purpose` | `research` → ■ 과학적 연구 |
| 데이터 활용 대상 자료 | `uses_hospital_data` 세부 | 서술 |
| **활용 주체** | `external_provision`, `recipient_orgs` | true → 제공받는 기관명 전부 기재 (누락 시 나중에 변경심의 필요) |
| **활용 기간** | `requested_period`, `irb_expiry_date` | ⭐ IRB 승인 필요 과제는 **IRB 만료일을 초과하지 않게** 설정 (제29조②) |
| 데이터 활용 계획 > 데이터 추출방법 | — | **데이터 건수 반드시 기재** |
| 데이터 활용 계획 > 데이터 활용 계획 | `includes_sensitive`, `includes_genomic` | 필요한 항목과 그 이유. 민감정보 제외 방침 명시 |
| 이용 및 제공 형태 | `data_export_type`, `data_state` | `raw_data` → 원시데이터 제공 사실 + 계약서 체결 계획 서술<br>`analysis_result` → 폐쇄형 분석실 분석 후 결과만 반출함을 서술<br>`none` → "원외 제공 없음" |
| 데이터 반복제공 여부 | `repeated_provision` | `once` → 1회 제공 / `repeated` → 반복제공( 회 예정) |
| 데이터 제공 방법 | — | ☐ 클라우드 독립 영역 업로드 ☐ 암호화한 저장장치(USB) |
| 안전한 파기 | `disposal_plan` | 종료 후 파기 절차 서술 (제27조④). false면 `[확인 필요: 파기 계획]` |
| 처리 환경 및 제공받는 자의 정보보호 수준 | `closed_analysis_room`, `data_combination`, `security_certification` | 분석 환경·출입통제·인증(ISMS/ISMS-P) 서술. 결합 시 **결합전문기관 명시** |

## 별지서식 11 — 항목별 가명처리 계획서

⛔ **슬롯에서 자동 생성할 수 없다.** 항목별 처리방법·처리수준은 연구 목적에 따라 달라진다. `pseudonymization-plan.md`를 읽고 사용자와 항목별로 확인한다.

슬롯이 도움이 되는 지점은 다음뿐이다.

| 판단 | 슬롯 |
|---|---|
| 민감정보 취급 방침을 물어야 하는가 | `includes_sensitive = true` |
| Dicom 서식이 추가로 필요한가 | 영상정보 포함 여부 |
| 「처리 없음」이 많을 때 경고 강도 | `data_export_type = raw_data`이면 경고를 강하게 |

## 별지서식 15 — 지속심의 신청서 고유 항목

| 서식 항목 | 슬롯 | 변환 |
|---|---|---|
| **연구계획서 변경** | `change_scope` | `duration_only`만 → ☑ 없음 / 그 외 값 포함 → ☑ 있음 |
| **정보주체 식별성** | `data_state`, `uses_linkage_file` | `identifiable` 또는 `uses_linkage_file = true` → ☑ 있음(상세기입) |
| **안전조치의무 실시** | `internal_mgmt_plan` | ☑ 실시 / ☑ 미실시(상세기입) |
| **이해 상충 변동** | — | 사용자 확인 |
| **활용 형태 변경** | `change_scope`에 `method` | ☑ 있음 → **변경심의 병행 필요** |
| **이용 주체 변경** | `change_scope`에 `subject` | ☑ 있음 → **변경심의 병행 + 승인번호 신규 부여** (제30조④) |
| **처리 환경 변경** | `change_scope`에 `safeguards`, `closed_analysis_room` | ☑ 있음 → **변경심의 병행 필요** |
| **처리 장소 변경** | `closed_analysis_room` | ☑ 있음 → **변경심의 병행 필요** |
| **제공받는자 변경** | `external_provision`, `recipient_orgs` | ☑ 있음 → **변경심의 병행 + 승인번호 신규 부여** (제30조④) |

⭐ 위 7개 중 하나라도 「있음」이면 **지속심의만으로는 부족하고 변경심의를 함께 신청**해야 한다 (제30조⑥). 이 경고를 반드시 출력한다.

⭐ `irb_approval_status != not_required`이면 **IRB 지속심의 승인서 / IRB 승인유효기간 연장 확인서** 첨부가 필요함을 반드시 안내한다 (제29조④).

## 별지서식 16 — 신속심의 신청서 고유 항목

|---|---|---|
| **심의 종류** ☐ 최소 위험 연구 환경(폐쇄 환경 분석실) | `closed_analysis_room` | true → ☑ |

## 별지서식 23 — 활용데이터 선정 사유 및 요구 수준표

별지서식 11과 **항목 목록을 일치**시킨다. 「항목 선정 사유」는 별지서식 11의 「처리수준」에 쓴 사유와 논리가 어긋나면 안 된다.

---

## 절대 지어내지 않을 항목

- DRB No., IRB 승인번호, 접수번호
- 데이터 건수, 대상자 수
- 날짜 (승인일, 만료일, 연구기간, 반출 승인일)
- 기관명, 부서명, 담당자명, 연락처
- **가명처리 방법·수준** (사용자 확인 없이 결정 금지)
- 수령기관의 보안 인증 보유 여부

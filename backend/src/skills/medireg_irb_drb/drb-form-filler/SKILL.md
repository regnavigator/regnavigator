# DRB 별지서식 작성

## 이 스킬의 경계

**이 스킬은 판정하지 않는다.** 어떤 서식을 쓸지는 `drb-triage`의 `verdict`와 `drb_submission_type`이 결정한다.

| 상황 | 열어야 할 서식 |
|---|---|
| `drb_submission_type = new` | 별지서식 10 + 11 (+ 3, 12-1, 12-2, 20, 21, 22, 25) |
| `= amendment` | 별지서식 13 + 14 |
| `= continuing` | 별지서식 15 + 14 + 23 |
| `= completion` | 별지서식 17 |
| `= supplementary` | 별지서식 18 + 14 |
| `= appeal` | 별지서식 19 |
| `= expedited` | 별지서식 16 + 24 + 10 + 23 |

⛔ **`verdict`가 없거나 `HOLD`이면 서식을 작성하지 않는다.** 먼저 `drb-triage`를 호출한다.
⛔ **스스로 심의 종류를 판단해서 서식을 고르지 않는다.**

## 절대 규칙

1. **모르는 항목은 비워두고 `[확인 필요: 항목명]`으로 표시한다.** DRB No., IRB승인번호, 데이터 건수, 날짜, 기관명은 특히 주의한다.
2. **가명처리 수준을 임의로 정하지 않는다.** 항목별 가명처리계획서의 처리방법·처리수준은 **연구 목적에 따라 달라지므로 사용자와 확인**한다. 근거 없이 "마스킹"이라고 채우지 않는다.
3. **"처리 없음"으로 두는 항목은 반드시 사유를 함께 쓴다.** 위원회가 가장 집중해서 보는 부분이다.
4. **모든 산출물 첫 줄에** `[AI 생성 초안 — 연구책임자 검토 필수]`
5. **환자 개인정보(이름, 등록번호, 주민번호 등)를 입력받거나 문서에 기재하지 않는다.** 항목명만 다루고 실제 값은 다루지 않는다.

## 작업 순서

1. `verdict`와 `drb_submission_type`을 확인하고 대상 서식을 결정한다
2. `references/form-registry.md`에서 해당 서식의 항목 구조를 확인한다
3. `references/field-mapping.md`에서 슬롯 → 항목 매핑을 적용한다
4. 신규심의라면 `references/pseudonymization-plan.md`를 읽고 항목별 가명처리계획을 함께 작성한다
5. 채워지지 않은 항목을 사용자에게 **한 번에 모아서** 묻는다
6. 초안을 생성하고, 미확인 항목 목록을 별도로 제시한다

## 출력 형식

기본은 **마크다운 표 형태의 항목별 초안**이다. 사용자가 파일을 원하면 docx로 생성한다.

```
[AI 생성 초안 — 연구책임자 검토 필수]

# 데이터 활용 신청서 초안
문서 기준: DRB 별지서식 10 / 의료정보데이터심의위원회 SOP ver1.0

| 항목 | 내용 | 출처 |
|---|---|---|
| 연구책임자 | [확인 필요: 소속·직위·성명·연락처] | — |
| IRB승인번호 | [확인 필요] (동시심의 진행 중이면 '심의 접수 증명서 첨부'로 기재) | triage: irb_approval_status=submitted |
| 처리 목적 | ■ 과학적 연구 | triage: data_purpose=research |
...

## ⚠️ 확인이 필요한 항목
- DRB No.
- 데이터 추출 건수
```

## 서식 원본 확보 현황

**DRB 별지서식 1~25는 SOP 본문에 서식 전문이 수록**되어 있어 실제 항목 구조를 그대로 사용할 수 있다. (별지서식 21은 표제가 `[서식 21]`로 표기되어 있다.)

원본 파일(hwp/docx)이 확보되면 `assets/`에 넣고 `references/form-registry.md`를 갱신한다.

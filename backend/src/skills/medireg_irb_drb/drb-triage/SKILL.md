# DRB 심의 판정

## 이 스킬의 경계

**이 스킬은 DRB 판정만 한다.** 판정 결과(Verdict 객체)를 생산하고 끝낸다.

| 하는 일 | 하지 않는 일 (다른 스킬 담당) |
|---|---|
| DRB 심의대상 여부 판정 | IRB 심의 판정 → `irb-triage` |
| DRB 심의 종류 결정(면제/신속/정규) | DRB 절차·제출서류 안내 → `drb-procedure` |
| **IRB↔DRB 선후관계·유효기간 계산** | DRB 서식 작성 → `drb-form-filler` |
| 판정 근거 조문 제시 | |

⭐ **IRB↔DRB 연동 규칙은 이 스킬이 소유한다.** 연동 규정(제27조②7호, 제29조②③④, 제30조⑥)이 전부 DRB SOP 조문이기 때문이다. IRB SOP에는 DRB에 관한 규정이 없다.

다만 **IRB 심의 종류 자체는 판정하지 않는다.** IRB 판정이 필요하면 `irb-triage`를 호출하고, 그 결과를 `irb_approval_status` 슬롯으로 받아 연동 규칙에만 사용한다.

## 절대 규칙

1. **추정 금지.** 사용자가 말하지 않은 사실을 추론해서 슬롯을 채우지 않는다.
2. **근거 없는 인용 금지.** `references/authorities.md`에 등록된 조문만 인용한다.
3. **애매하면 `HOLD`.** 특히 **심의대상을 면제·해당없음으로 판정하는 오류는 절대 허용되지 않는다.**
4. **원시데이터 반출·외부 제공·가명정보 결합이 있으면 신속심의로 판정하지 않는다.** 애매하면 `HOLD`.
5. **예비판단임을 매번 고지한다.**

## 판정 절차

### 1단계 — DRB 트랙 해당 여부

병원이 보유·관리하는 **의료정보데이터**(진료·검사·영상·병리·처방·임상연구·유전체 정보 및 이와 관련된 데이터 일체)를 **교육·연구 등의 목적으로 이용·제공·반출·결합**하는가?

- 아니오 → `NOT_APPLICABLE`로 종결
- 예 → 2단계

### 2단계 — 슬롯 채우기

`references/slots.md`를 읽고 **현재 판정에 필요한 슬롯만** 확인한다. 전체를 다 묻지 않는다.

- 추출한 값은 사용자에게 확인시킨다
- 결정적 슬롯이 비어 있으면 **한 번에 하나씩** 묻는다
- 질문 7개를 넘겨도 결정적 슬롯이 `UNKNOWN`이면 `HOLD`

### 3단계 — 위험도 게이트

아래가 하나라도 있으면 **신속심의로 판정하지 않는다.** 정규심의로 기울거나 `HOLD`.

- **원시데이터 반출** (가명처리된 개별 환자 단위 데이터를 외부로 복제·이동)
- **외부기관 제공**
- **결합전문기관을 통한 가명정보 결합**
- 유전체정보 포함
- 재식별 위험이 우려되는 **연결파일** 사용

### 4단계 — 심의 종류 판정

`references/drb-review-type.md`를 읽고 노드를 순서대로 따라간다. 각 노드의 질문·답변·근거를 trace에 기록한다.

**순서**: 심의면제 기준(제32조⑦) → 신속심의 기준(제32조①) → 정규심의(제24조③)

⭐ 심의면제 기준 4가지는 판정에서 자주 놓치는 부분이다. **반드시 먼저 확인한다.**
- IRB 승인된 건 중 **가명처리가 필요없는** 데이터
- **개인정보 미포함**
- **동의 후 수집한** 데이터
- **증례보고서(CRF)를 통해 수집된** 데이터

### 5단계 — IRB 연동 계산

`irb_approval_status`가 `not_required`가 아니면 **반드시** `references/irb-linkage.md`를 읽고 다음을 계산한다.

1. IRB와 **동시 진행이 가능한지**
2. **실효 만료일** = min(IRB 승인만료일, DRB 승인만료일)
3. 연장 준비 **순서와 기한**
4. **변경심의 병행**이 필요한지

## 출력 형식

답변 말미에 **반드시** 아래 구조화 블록을 붙인다.

```json
{
  "rulepack_version": "cnuhh-drb-2026.07",
  "drb": {
    "verdict": "NOT_APPLICABLE | EXEMPT | EXPEDITED | FULL_BOARD | HOLD",
    "trace": [{"node_id": "", "question": "", "answer": ""}],
    "cited_loci": [""],
    "unknowns": [""]
  },
  "irb_linkage": {
    "concurrent_submission_possible": true,
    "effective_expiry": "min(IRB, DRB)",
    "notes": [""]
  },
  "used_slots": {}
}
```

| verdict | 의미 |
|---|---|
| `NOT_APPLICABLE` | DRB 심의 대상이 아님 |
| `EXEMPT` | 심의면제. ⚠️ DRB에서 심의면제는 **신속심의의 한 유형**이므로 위원회 절차를 거치지 않는다는 뜻이 아니다 (제24조④6호) |
| `EXPEDITED` | 신속심의 (전문위원 2명) |
| `FULL_BOARD` | 정규심의 |
| `HOLD` | 정보 부족 또는 판단 여지 있음 |

**사용자에게 보여줄 서술 순서**

1. **결론** — DRB 판정 한 줄
2. **IRB 연동** — 해당하면 동시 진행 가능 여부와 실효 만료일
3. **판단 경로** — 확인한 질문과 답변
4. **근거** — 조문 원문 + 출처
5. **다음 단계** — 절차·서류는 `drb-procedure`, 서식 작성은 `drb-form-filler`
6. **불확실 요소**

**고지 문구 (매번 고정)**

> 본 판단은 화순전남대학교병원 의료정보데이터심의위원회 표준운영지침서 ver1.0(시행 2026.07.01)을 기준으로 한 **예비판단**입니다. 최종 심의대상 여부와 심의 종류는 위원회 사무국의 검토로 확정됩니다.

## IRB 판정이 함께 필요한 경우

사용자의 연구가 **사람을 대상으로 하거나 인체유래물을 다루면** IRB 심의도 별도로 필요할 수 있다. 이 스킬은 IRB를 판정하지 않으므로, 다음과 같이 안내하고 `irb-triage`를 호출한다.

> 이 연구는 DRB 외에 IRB 심의 대상일 수 있습니다. IRB 판정을 함께 확인하시겠습니까?

## HOLD를 내야 하는 상황

- 결정적 슬롯이 `UNKNOWN`이고 사용자가 답할 수 없는 경우
- 3단계 위험도 게이트에 걸리는데 신속심의 요건도 일부 충족하는 경우
- 결합전문기관 결합, 다기관 공용 데이터위원회 위탁 등 결정트리에 없는 유형
- 위원회 구성·정족수 판단이 필요한 경우 (**위원회 규정 미확보**)

HOLD 시에는 **무엇을 몰라서 보류했는지**를 명시하고 사무국에 무엇을 물어야 하는지 알려준다.
